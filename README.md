# 蟻級單元導航模擬器(ant_sim)

以「蟻級單元」凍結規格為藍本的 2D 模擬器與機上演算法。目的:在買零件之前,
把演算法階梯的第 1–5 階在**誠實的雜訊**下跑通,並把每一個門檻與教訓帶到實機。

**鐵律:`brain.py` 是未來 ESP32-S3 韌體的 1:1 藍本,只准讀 `SensorPacket` 與
相機影像,嚴禁引用任何真值。** 真值只交給實驗腳本當裁判(= 天花板相機的角色)。

> 本版(2026-08-22)為**基線封版**:World/PanoCamera 架構整合完成、
> 兩座模擬-實機橋(光流去旋轉、球鏡展開校正)搭通、四實驗全數重跑。
> 舊版數字已作廢,勘誤見文末。

## 快速開始

```bash
pip install numpy matplotlib scipy   # scipy 僅工具腳本用
python3 smoke_test.py                # 校定工具:符號、FFT、門檻表、打滑、光流偏移(五段)
python3 experiments/exp1_homing.py   # 中央覓食五趟,四配置對打(~3 分鐘)
python3 experiments/exp2_compass.py  # 航向時間線 + 關燈時段(秒級)
python3 experiments/exp3_catchment.py # 快照歸巢集水區地圖(~1 分鐘)
python3 experiments/exp4_route.py    # 熟悉度循路回放,每起點 5 seeds(~2 分鐘)
python3 mirror_calib.py              # 球鏡展開 LUT 生成 + 閉環驗證(橋二)
python3 make_demo.py                 # 錄一趟完整任務成 GIF
```

圖與資料輸出到 `out/`。

## 架構(World / PanoCamera 拆分)

```
config.py ── 單一參數源(凍結規格・雜訊・門檻,每個門檻附校定法)
world.py  ── World(幾何+光照狀態;step() 是唯一改狀態入口)
             PanoCamera(純函數觀測;參數建構時複製,可多台並存)
sim.py    ── 200 Hz 物理積分+雜訊工廠,產生 SensorPacket;裁判介面 gt_*
brain.py  ── ★機上演算法(=韌體藍本),鐵律牆內
experiments/, smoke_test.py, mirror_calib.py ── 裁判與校定工具(牆外)
```

呼叫契約(破壞任一條 = 靜默失真):sim 每個 tick 必呼叫 `world.step(DT, rng)`
(否則光照漂移凍結,症狀是「一切變好」);`PanoCamera.render` 回傳
`(img, valid_light)` tuple;每個封包先 `HeadingBank.on_packet` 再
`PathIntegrator.on_packet`(PI 讀航向);物理必須保證車不入圓筒
(render 假設此事,sim 已補碰撞)。

## 演算法階梯對應

| 階 | brain.py 類別 | 一句話 |
|---|---|---|
| 1 | `Controller`(三相繞行)、`Forager`(OU 隨機遊走) | Braitenberg 式反射與覓食 |
| 2 | `HeadingBank` + `PathIntegrator` + `Homer` + `SearchSpiral` | 箭蟻回家向量 + Wehner 系統性搜尋 |
| 3 | `ridf()` 視覺羅盤(FFT 圓周相關,0.07 ms/次) | 巢錨定絕對航向 |
| 4 | `SnapshotHomer`(run-and-tumble 沿 IDF 梯度) | Cartwright–Collett / Zeil 快照歸巢 |
| 5 | `RouteFollower`(完美記憶版熟悉度) | Baddeley 2012 的基準線 |

## 實驗結果(2026-08 本版實測;舊表作廢)

**實驗一・中央覓食五趟**(每趟覓食 25 s 後歸巢;n=12;到家誤差中位數 cm)。
D 配置本版起含完整光流鏈路(安裝偏移污染 + 陀螺去旋轉):

| 配置 | 趟1 | 趟2 | 趟3 | 趟4 | 趟5 |
|---|---|---|---|---|---|
| A 純編碼器 | 63.8 | 63.3 | 48.4 | 107.4 | 101.0 |
| B +陀螺 | 4.3 | 11.1 | 18.5 | 15.1 | 16.1 |
| C +巢錨定視覺 | 3.4 | 5.4 | 6.4 | 6.5 | 6.0 |
| D C+光流打滑抑制 | 3.4 | 3.5 | 5.1 | 4.6 | 6.7 |

四條結論不變:打滑判編碼器死刑;陀螺短期漂亮但溫漂逐趟複利;視覺錨定把
誤差**壓平**在鎖半徑;C≈D(靠泊精度由鎖半徑決定,光流價值在著陸距離與
搜尋時間)。去旋轉的獨立驗證:20 s 蛇行下,2 cm 安裝偏移使 PI 終點誤差
中位 3.8→5.9 cm,修正後**精確回到 3.8 cm**。

**實驗二・航向時間線(關燈 30–55 s)**:最大|航向誤差|° enc/gyro/fused =
關燈前 31.3/1.8/2.9、關燈中 24.1/4.6/**2.1(靠陀螺優雅退化)**、
復燈後 59.8/9.4/**2.5(鎖巢瞬間彈回)**;復錨事件 27/55/92/119 s。

**實驗三・快照歸巢集水區**(71 起點、50 s 逾時):總成功率 **30%**,
空間結構:距巢 0–0.5 m 成功 69%、0.5–1 m 41%、1–1.6 m 11%、更遠 14%;
成功案例最終距離中位數 3.3 cm。**快照歸巢是半徑約 0.8–1 m 的區域技能**
(Zeil 2003),此即階 5 的存在理由。

**實驗四・循路回放**(31 張視圖 @8 cm;協定升級為**每起點 5 seeds**):
路上起步 **5/5 到達**、偏差中位 3.0 cm(max 10.7);+14 cm 側偏 **5/5**、
13.2 cm;−17 cm+20° 複合偏移 **1/5**、70.6 cm。舊版「三者皆到達」是 n=1
的幸運抽籤(舊堆疊重測同為 1/5)——修正後的結論:**循路是「路廊技能」,
路上與 ≤14 cm 側偏可靠,17 cm+20° 已出眼熟集水區**,與實驗三互為鏡像。

## 六條實戰教訓(每條都是被模擬器擊斃後驗屍得來)

1. **小場地沒有「遠方」。** 單一快照絕對羅盤有效半徑僅 6–10 cm,視差是
   物理不是雜訊。→ 羅盤改**巢錨定**:只在視覺確認到巢時錨定並把 PI 歸零。
2. **搜尋幾何會跟自己的感測防線打架。** 螺旋轉太快觸發陀螺閘控;開環螺旋
   漂移把巢留在盲區。→ 降速換小迴轉,**用 PI 閉環**繞「相信的巢」畫擴張圈。
3. **光照增益漂移淹掉完美燈況校定的門檻。** 症狀「第一趟成功、之後全滅」。
   → 所有匹配前**光度正規化**,門檻用正規化單位重校。(勘誤:舊版 OU 實作
   漏乘 dt,實際只有 ±1.5% 快漂;本版修正為規格的 ±5%@8 s——因 norm 的
   仿射不變性,修正後對演算法統計幾乎無影響,這本身就是 norm 的價值證明。)
4. **牆面天際線準週期,給出自信但大錯的角度。** → 視覺角度須與陀螺先驗
   一致(±30°)才融合;鎖巢判定(旋轉不變)從融合閘解耦。
5. **P 控制器 + 單純反射 = 圓筒死鎖。** → 三相反射:倒退轉開 → **直走
   繞行 1 秒**打破對稱 → 還控制權。
6. **n=1 不是結論。** 實驗四舊版單次抽籤把「出集水區的起步」記成成功,
   新舊堆疊各跑 5 seeds 才現形(皆 1/5,fam 從第一幀就 ~0.69)。→ 涉及
   邊界能力的實驗一律多 seeds;離線指標(fam)在起步當下就能預告成敗。

門檻總表(正規化單位;`smoke_test.py` 可重新量測,量測方向須固定——
帶域門檻各向異性,校定值綁定校定方向):羅盤帶域近距 `COMPASS_NEAR=0.60`
(≈6 cm)、鎖巢全圖 `NEST_LOCK_FULL=0.060`(≈6 cm)、快照到家 `0.040`、
RIDF 信心 `0.22`(關燈實測 ~0.05)、陀螺一致性 `±30°`、陀螺閘控 `80°/s`。

## 實機校定手冊(對應 smoke_test 的五段)

1. 機器人置於巢、面向 0°:原地轉已知角度(±10/30/80°),驗 RIDF 符號與
   精度、conf 正常值域。
2. 已知小位移(3/6/10/20 cm,用尺,**方向固定**)→ 填三個門檻。
3. 關燈一次:確認 conf 掉到門檻以下。
4. 混合行駛 20 s 對照天花板相機:量實際打滑,回填 config。
5. 原地交替旋轉 15 s:flow_dx/DT 對陀螺 ω 回歸,斜率 = −安裝側向偏移,
   回填 `FLOW_MOUNT_Y`(模擬自校:真值 20 mm 量回 18.4 mm,差額即刻度誤差)。

## 韌體移植路徑(ESP32-S3)

- **Core 0(200 Hz)**:`HeadingBank.on_packet`、`PathIntegrator.on_packet`
  (含光流去旋轉一行)、`Controller.mix`、PID 與安全。負載個位數 %。
- **Core 1(12–15 fps)**:取像 → **`pano_lut.h` 展開(4-tap 雙線性——最近鄰
  會把 RIDF 次像素估計咬出 ~1.5° 偏差)** → 正規化 → `ridf`/`img_diff`。
  FFT 用 esp-dsp `dsps_fft2r_fc32`,估 1–3 ms/幀。幀須配曝光當下的陀螺航向。
- **球鏡幾何(mirror_calib 推導)**:等效視點高 **14.8 cm**(config 待回填,
  非中心散佈僅 ±0.5 mm)、仰角 55°/−5° 可達(極限 77°);**240 px 裁切下
  羅盤帶徑向只佔 5.1 px,實機裁切建議 ≥480 px** 或下修 EL_TOP(改了要照
  config 警語重推 COMPASS_ROWS 並重跑門檻)。
- **記憶體**:視圖以 **uint8 存 PSRAM(3 KB/張)**,載入路線時一次展開
  正規化+FFT;31 張路線原始 93 KB。
- 類別→模組:`SensorPacket`=序列封包(需註明 flow_dx **未**去旋轉,由
  pi.cpp 修正)、`HeadingBank`→heading.cpp、`PathIntegrator`+`SearchSpiral`
  →pi.cpp、`SnapshotHomer`→snapshot.cpp、`RouteFollower`→route.cpp、
  `Controller`→reflex.cpp。因鐵律,逐行對翻即可。

## 已知限制與下一步

- 成像是剪影模型(無紋理/鏡面反射;球面高光待實照);球鏡展開已有 LUT
  工具與閉環驗證(同位姿 RIDF +0.17°、+30° 測 +30.35°),實照精修待硬體。
- 編碼器模擬缺**減速箱背隙**(換向時編碼器先動輪後動)與**堵轉**模式
  (被擋時實機可能輪不動而非打滑);實機校定第 4 段會量到。
- 觸鬚有正面盲區:最小圓筒可從 ±34° 兩鬚之間溜過(模擬忠實重現);
  實機考慮第三根中央觸鬚,或用 MPU6050 加速度計(現閒置)偵測碰撞/堵轉。
- 光流只模前向分量;PAA5100 側向軸未用;刻度隨 squal 變化未模。
- OV2640 是 rolling shutter,快轉是傾斜畸變非水平拖影——陀螺閘控本就擋掉
  快轉幀(閘控的第五個用途);相機視點須在旋轉軸上(桅杆同軸公差)。
- 下一階:階 6 環吸引子(換掉 `HeadingBank`)、階 7 多機費洛蒙(裁判介面
  已預留)。
